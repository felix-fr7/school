# Student Login Fix Report

## Issue
Students created in the class were unable to login to the system.

## Root Cause
The password was being hashed **twice** during student creation:

1. **First hashing** occurred in the route handler (`backend/src/routes/classController.js`) before creating the user
2. **Second hashing** occurred automatically via the User model's pre-save hook (`backend/src/models/User.js`)

This double hashing caused the stored password hash to never match the login attempt, since `comparePassword` would compare the plain text password against a double-hashed value.

### Code Analysis

**Before (Incorrect - Double Hashing):**
```javascript
// In backend/src/routes/classController.js
const hashedPassword = await bcrypt.hash(finalPassword, saltRounds); // First hash

const student = await User.create({
  email: dummyEmail,
  password: hashedPassword, // Already hashed
  // ... other fields
});
// User model's pre-save hook hashes again (Second hash)
```

**After (Correct - Single Hash):**
```javascript
// In backend/src/routes/classController.js
const student = await User.create({
  email: dummyEmail,
  password: finalPassword, // Plain password
  // ... other fields
});
// User model's pre-save hook handles hashing automatically
```

## Changes Made

### 1. Fixed `backend/src/routes/classController.js`
- Removed manual password hashing in the `POST /api/class-controller/students` endpoint
- The User model's pre-save hook now handles password hashing automatically
- Updated comments to clarify that password will be hashed by the model

### 2. Updated `frontend/src/screens/LoginScreen.jsx`
- Changed the student ID placeholder from `STU-2026-001` to `STU-0001` to match the actual format generated by the backend

## Verification

After these changes:
1. New students created via the class controller will have properly hashed passwords
2. Students can login using their student ID (e.g., `STU-0001`) and password
3. The default password for new students is `Student@123`

## Notes

- The password reset endpoint (`PUT /api/class-controller/students/:id/reset-password`) correctly uses manual hashing because it uses `findByIdAndUpdate` which does NOT trigger Mongoose middleware
- The controller file (`backend/src/controllers/classController.js`) already had the correct implementation and was not affected
